# ADR-016 staging bootstrap draft

**Not deployed.** The template is a proposed implementation of ADR-016's remote-state and deployment-role prerequisite. It does not satisfy the live proof gate. Account `792394000571`, resource region `us-east-2`; no Production application resources.

CloudFormation owns the eight bootstrap resources so Terraform can use encrypted remote state from its first real plan. The state bucket is private, AES256 encrypted, versioned and retained. Its policy permits object access only to the exact state role and denies deletion of the state key and versions. Only the lock object may be deleted. The lock table has encryption, deletion protection and no TTL. S3 native locking is also enabled: HashiCorp now deprecates DynamoDB locking; the table temporarily preserves doc 09's existing architecture rather than silently changing it.

Two distinct GitHub OIDC roles trust only `repo:MichalKuderski/AutoBureau:environment:staging`, with audience `sts.amazonaws.com`. They additionally pin the live repository ID `1336298759`, owner ID `177895094`, environment `staging`, and exact refs `refs/heads/main` or `refs/pull/5/merge`. Current AWS documentation supports these claim keys. GitHub's protected staging branch rules remain part of this boundary. The normal `main` rule must remain; a temporary PR #5 exception requires the explicit authorization requested after automatic review rejected it. Restore the exact GitHub baseline after this work and remove temporary PR trust when no longer needed.

The state role accesses one state key and exact lock/checksum keys. The deployment role initially has **read permissions only** for the named quarantine bucket, two upload roles and Vercel provider. A managed permissions boundary limits future plan-derived deployment grants to those resources. It cannot edit either boundary, the bootstrap roles or state; create credentials; pass a role; delete infrastructure; or access document contents. Each upload role must have the separately managed quarantine-only boundary, which the deployment role cannot remove. IAM boundaries limit grants; they do not grant access by themselves.

Fixed physical names are deliberate: they permit exact policy scope and conflict detection. This stack has no runtime worker, model, continuous compute, domain, SMTP or financial-provider resources. Retaining resources means stack removal is not cleanup; never delete or replace state as a rollback shortcut.
