## Defects found and forward fixes

Two permissive-policy combinations admitted routing reads beyond the intended digest authority. A PUBLIC household policy was OR-combined with each restricted runtime's digest SELECT policy. Setting household context could therefore reveal route rows without the required matching digest. Regression assertions reproduced the defects before correction; those earlier RED/GREEN runs remain separate from the exact-candidate suite below.

1. **Stripe route isolation:** migration 47, `20261003000001_stripe_route_digest_isolation`, limits the existing household policy to the application/retention/deletion-verification roles. The billing runtime can satisfy only its digest lookup policy. Regression coverage also checks checkout owner/owner-ID, intent binding, direct billing write privilege, revision/lease, deletion fence and migration-ledger authority. See [Stripe integration assertions](https://github.com/MichalKuderski/AutoBureau/blob/13766613c0ddc55ffb5ad0438550c5cbcd2d8fc0/packages/db/tests/integration/stripe-test-checkout.integration.test.ts).
2. **Plaid route isolation:** migration 48, `20261003000002_plaid_route_digest_isolation`, limits the household policy to the two existing privacy reader roles and preserves runtime insertion through a separate household-bound INSERT-only policy. Digest-only SELECT remains unchanged. Real restricted-role Item insertion still creates the route and cursor under the existing guards and audit. See [Plaid integration assertions](https://github.com/MichalKuderski/AutoBureau/blob/13766613c0ddc55ffb5ad0438550c5cbcd2d8fc0/packages/db/tests/integration/plaid-local-lifecycle.integration.test.ts).

Both fixes preflight the exact old policy/RLS posture, take the policy-alteration table lock with a 5-second acquisition limit, and bound statements to 60 seconds. They change policy metadata only: no data rewrite or new grant, runtime identity, trigger or function authority. Each migration has its own transaction; the two-migration chain must not be described as one atomic unit. If the second fails after the first commits, retain the applied journal and use the reviewed forward-fix procedure. Never restore either permissive policy to manufacture rollback success.
